# 유저 스토리 (User Stories)

## 분류 방식: 기능 기반 (Feature-Based)
## 스토리 규모: 대형 (Epic 수준, 7개)
## 수용 기준: 체크리스트 형식
## 우선순위 기준: 기술 복잡도 우선

---

## Epic 1: 시세 대시보드 및 분류 체계

**As a** 영양사/MD/바이어  
**I want to** 농수산물·축산물·가공식품의 도소매 시세를 분류 체계별로 필터링하여 조회하고 싶다  
**So that** 내가 관심 있는 품목의 현재 가격과 도소매 갭을 한눈에 파악할 수 있다

### 수용 기준 (Acceptance Criteria)
- [ ] 식자재가 대분류(구황작물, 수산물, 채소류, 과일류, 축산류, 가공식품)로 분류되어 표시된다
- [ ] 카테고리 탭을 클릭하면 해당 분류의 품목만 필터링된다
- [ ] 각 품목에 도매가, 소매가, 시세 갭(%)이 표시된다
- [ ] 품목명 또는 카테고리로 검색/필터링이 가능하다
- [ ] 데이터는 KAMIS API 및 공공데이터포털에서 실시간 조회된다
- [ ] 로딩 시간이 3초 이내이다
- [ ] IT에 익숙하지 않은 사용자도 직관적으로 사용할 수 있는 UI이다

### 관련 페르소나
- 김영희 (영양사): 주문 전 시세 확인
- 박준호 (MD): 일별 시세 모니터링
- 이수진 (바이어): 구매 시점 판단 근거

### 기술 복잡도: ★★★☆☆
### 우선순위: P1 (핵심 기반 기능)

## Epic 2: 시세 추이 그래프 + 가격 이상치(Spike) 뉴스 매핑

**As a** MD/바이어  
**I want to** 특정 품목의 가격 추이 그래프를 보면서, 가격이 급등/급락한 시점에 관련 뉴스를 확인하고 싶다  
**So that** 가격 변동의 원인을 빠르게 파악하고 향후 추이를 예측할 수 있다

### 수용 기준 (Acceptance Criteria)
- [ ] 품목 선택 시 일별/주별/월별 가격 추이 라인 차트가 표시된다
- [ ] 가격 이상치(Spike) 시점이 차트에 시각적으로 구분된다 (색상/마커)
- [ ] Spike 포인트에 마우스 오버 시 커스텀 툴팁에 뉴스 헤드라인이 표시된다
- [ ] 뉴스 헤드라인 클릭 시 원문 URL로 이동한다
- [ ] Spike 감지 알고리즘이 통계적 기준(표준편차 등)으로 동작한다
- [ ] 뉴스와 시세 이벤트가 시간 기준으로 정확히 매핑된다
- [ ] Recharts CustomTooltip으로 구현된다

### 관련 페르소나
- 박준호 (MD): 가격 변동 원인 분석
- 이수진 (바이어): 시즌별 가격 패턴 파악

### 기술 복잡도: ★★★★☆
### 우선순위: P1 (시각적 임팩트 + 기술 복잡도 높음)

## Epic 3: AI 기반 메뉴/레시피 제안 + 식수별 비용 시뮬레이션

**As a** 영양사  
**I want to** AI가 현재 시세를 반영한 메뉴와 레시피를 제안하고, 식수별 총 원가를 시뮬레이션하고 싶다  
**So that** 예산 내에서 영양 균형 잡힌 메뉴를 효율적으로 계획할 수 있다

### 수용 기준 (Acceptance Criteria)
- [ ] 식수(100식, 1000식, 10000식 등)를 입력할 수 있다
- [ ] AI가 현재 시세 기반으로 메뉴/레시피를 제안한다
- [ ] 각 레시피에 재료 목록, 1인분 단가, 총 원가가 표시된다
- [ ] 예산 제한을 입력하면 예산 내 가능한 메뉴 조합을 추천한다
- [ ] 영양 정보(칼로리, 단백질, 탄수화물 등)가 함께 표시된다
- [ ] 시뮬레이션 결과를 비교할 수 있다 (여러 메뉴 옵션 비교)
- [ ] AI 응답은 컨설턴트 스타일로 분석+추천+근거를 구조화하여 제시한다

### 관련 페르소나
- 김영희 (영양사): 주간 메뉴 계획 + 원가 계산

### 기술 복잡도: ★★★★★
### 우선순위: P1 (AI 활용도 핵심)

---

## Epic 4: 대체 식자재 원가 절감 전략 제안

**As a** 영양사/바이어  
**I want to** 특정 식자재 가격이 급등했을 때, 대체 가능한 식자재와 이를 활용한 레시피를 추천받고 싶다  
**So that** 메뉴 품질을 유지하면서 원가를 절감할 수 있다

### 수용 기준 (Acceptance Criteria)
- [ ] 특정 식자재를 선택하면 대체 가능한 식자재 목록이 표시된다
- [ ] 대체 식자재는 온톨로지(지식 그래프) 관계에 기반하여 추천된다
- [ ] 각 대체 식자재의 현재 가격과 원래 식자재 대비 절감률이 표시된다
- [ ] 대체 식자재를 활용한 레시피가 함께 제안된다
- [ ] 가격 급등 감지 시 자동으로 대체 식자재를 알림/제안한다
- [ ] AI 추천의 근거(온톨로지 관계, 영양 유사성 등)가 명시된다

### 관련 페르소나
- 김영희 (영양사): 상추 흉작 → 대체 식재료 탐색
- 이수진 (바이어): 양파 가격 상승 → 대파/쪽파 대체 검토

### 기술 복잡도: ★★★★★
### 우선순위: P1 (온톨로지 + AI 결합, 기술 복잡도 최고)

## Epic 5: 대화형 AI 챗봇 (RAG 기반)

**As a** 영양사/MD/바이어  
**I want to** 자연어로 현재 시세, 시장 동향, 대체 식자재 등을 질문하고 데이터 기반 답변을 받고 싶다  
**So that** 복잡한 대시보드를 탐색하지 않고도 빠르게 필요한 정보를 얻을 수 있다

### 수용 기준 (Acceptance Criteria)
- [ ] 우측 하단 플로팅 버튼으로 챗봇을 열고 닫을 수 있다
- [ ] 챗봇 열림/닫힘에 부드러운 애니메이션이 적용된다
- [ ] 사용자가 자연어로 질문을 입력할 수 있다
- [ ] AI가 RAG(Bedrock Knowledge Bases) 기반으로 사실에 근거한 답변을 생성한다
- [ ] 답변에 타이핑 애니메이션 효과가 적용된다
- [ ] 모든 답변에 데이터 출처(API명, 날짜)가 표시된다
- [ ] 답변 신뢰도가 낮을 경우 "확인 필요" 경고가 표시된다
- [ ] 컨설턴트 스타일: 분석 → 추천 → 근거 구조로 응답한다
- [ ] LangChain 기반으로 백엔드 체인이 구현된다

### 관련 페르소나
- 김영희 (영양사): "상추 대신 뭘 쓸 수 있나요?"
- 박준호 (MD): "냉동 윙봉 현재 유통가와 시세는?"
- 이수진 (바이어): "양파 가격 상승 원인과 전망은?"

### 기술 복잡도: ★★★★★
### 우선순위: P1 (RAG + LangChain + Bedrock, 기술 복잡도 최고)

## Epic 6: 뉴스 크롤링 및 시세 이벤트 연동

**As a** MD/바이어  
**I want to** 농수산물 관련 뉴스가 자동으로 수집되고, 시세 변동 이벤트와 연결되어 보고 싶다  
**So that** 시장 상황을 별도로 검색하지 않고도 대시보드에서 바로 파악할 수 있다

### 수용 기준 (Acceptance Criteria)
- [ ] 네이버 뉴스 API로 농수산물 관련 뉴스가 자동 수집된다
- [ ] 농림축산식품부/해양수산부 보도자료가 수집된다
- [ ] 수집된 뉴스가 식자재 키워드로 분류/태깅된다
- [ ] 뉴스 이벤트가 시세 변동 시점과 시간 기준으로 매핑된다
- [ ] 뉴스 기사는 벡터 임베딩되어 RAG Knowledge Base에 적재된다
- [ ] 뉴스 이벤트 데이터는 RDB(PostgreSQL)에 저장된다
- [ ] 크롤링 실패 시 캐시된 데이터로 자동 전환된다 (Fallback)

### 관련 페르소나
- 박준호 (MD): 가격 변동 원인 뉴스 확인
- 이수진 (바이어): 시장 동향 모니터링

### 기술 복잡도: ★★★★☆
### 우선순위: P2 (데이터 파이프라인, Epic 2의 데이터 소스)

## Epic 7: 온톨로지 기반 식자재 지식 그래프

**As a** 시스템  
**I want to** 식자재 간의 관계(대체 가능, 같은 카테고리, 영양 유사 등)가 지식 그래프로 구조화되어 있어야 한다  
**So that** AI가 대체 식자재 추천 시 근거 있는 관계 기반 추천을 할 수 있다

### 수용 기준 (Acceptance Criteria)
- [ ] Amazon Neptune에 식자재 노드와 관계가 저장된다
- [ ] 관계 유형: 대체가능(substitutable), 같은분류(sameCategory), 영양유사(nutritionSimilar), 조리호환(cookingCompatible)
- [ ] 최소 50개 이상의 주요 식자재가 노드로 등록된다
- [ ] 각 식자재 노드에 카테고리, 영양정보, 시즌 정보가 속성으로 포함된다
- [ ] Gremlin 또는 openCypher 쿼리로 관계 탐색이 가능하다
- [ ] 온톨로지 데이터가 대체 식자재 추천 API에서 활용된다

### 관련 페르소나
- 시스템 내부 (Epic 4, Epic 5의 기반 데이터)

### 기술 복잡도: ★★★★★
### 우선순위: P1 (다른 Epic의 기반 인프라)
